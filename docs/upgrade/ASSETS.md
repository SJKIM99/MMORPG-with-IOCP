# Higgsfield 생성 기록 (고도화)

[공통 규칙 7] 순서: **잔액 확인 → 한 개로 시험 → 게임 화면에 넣어 녹화로 확인 → 통과하면 일괄 생성.**
한 번에 잔액의 30% 이상을 쓰는 생성은 사용자에게 먼저 묻는다. 이 파일에 생성 목록 · 사용량을 남긴다.

## 1-D 파이프라인 — 동작 영상 → 프레임

`tools/assetgen/motion.py` (원본은 저장소 밖 `~/.cache/harven-assetgen/raw/motion`)

```bash
cd tools/assetgen
python3 motion.py compose pc_knight_run     # 아틀라스의 기준 동작(walk1)을 자홍 바탕 512px 캔버스에 1.6배로 → 시작 그림
#   → Higgsfield: media_upload → PUT → media_confirm → generate_video(start_image = end_image = 그 그림)
#   → motion_jobs.json에 media · job · url 기록
python3 motion.py fetch pc_knight_run       # 영상 내려받기
python3 motion.py build                     # 전부 → Client2D/assets/sprites/motion_0.png + motion.txt (+ review/ 검토 그림)
```

| 단계 | 어떻게 | 왜 |
|---|---|---|
| 시작 그림 | 기본(서기) 그림이 아니라 **첫 걸음(walk1)** 을 시작 · 끝 그림으로 | 서기에서 시작하면 영상 앞부분이 "출발"이라 반복 구간이 짧아진다. 달리는 자세끼리 이으면 영상 전체가 달리기 |
| 바탕 | 캐릭터에 없는 단색(서약기사 · 각인술사: 자홍 `#FF00FF`, 붉은 목도리를 두른 밤사냥꾼은 초록으로 예정) | Higgsfield 배경 제거(크레딧)를 쓰지 않고 로컬 키잉 |
| 주기 | 1/4 크기 프레임끼리 차이 → 평균 D[i, i+L]이 가장 작은 L. 처음 · 끝 8장은 빼고(시작 · 끝 그림으로 끌려가는 구간) | 서약기사 24장 · 각인술사 16장 — 둘 다 뚜렷한 최소 |
| 위상 | 시작 그림과 닮고 한 주기 뒤와도 닮은 곳에서 자른다 → 0번 = walk1 자세 = 게임 걸음 위상 π/2 | 게임은 걸음 위상(이동 거리 ÷ 보폭)으로 프레임을 고른다 — 발이 미끄러지지 않는다 |
| 장수 | 주기의 약수 중 주문 장수(12)에 가장 가까운 것 | 16장 주기에서 12장을 뽑으면 1 · 2장씩 건너뛰어 걸음이 울컥였다 |
| 키잉 | 키 = min(R, B) − G(자홍). 가장자리는 바탕색을 덜어 내고(C = aF + (1−a)K), 자홍↔초록 축을 무채색은 ±6으로 누르고, 알파를 반 픽셀 조이고, 몸에서 떨어진 옅은 빛무리를 지우고, 가장자리 색은 안쪽 색으로 | 영상은 색 해상도가 절반(4:2:0)이라 가는 칼날이 초록 · 분홍으로 물들었다. 각인술사 지팡이 빛이 바탕에 번진 막이 회색 얼룩으로 남았다 |
| 발 기준점 | 카메라가 고정이므로 한 주기 전체가 **같은 바닥점**(시작 그림의 walk1 기준점 + 0번 프레임 평행 이동) | 프레임마다 발바닥에 맞추면 공중에 뜬 순간이 땅에 눌려 몸의 오르내림이 사라진다 |
| 크기 | 영상 px × 캔버스 / (영상 폭 × 1.6) = 아틀라스 px, 기준높이 = walk1과 같게(230) | 새 프레임과 기존 13장이 같은 배율 — 섞여도 튀지 않는다 |
| **발 쓸림 검사** | 가장 낮은 띠(가는 칼 · 지팡이는 9px 열림으로 지움)의 가로 위치가 뒤로 가는 속도 × 주기 → 칸/주기. 게임 보폭 1.9의 ±20%면 통과 | 제자리 걸음 영상은 게임에서 디딘 발이 몸과 함께 미끄러진다 — 눈으로 보기 전에 숫자로 거른다 |

게임(`render/ActorSprites`): `pc_<직업>_run00…`이 4장 이상 있으면 앞모습 걷기를 그 프레임으로(걸음 위상으로 고름, 몸 흔들기는 0.6px로 줄임 —
오르내림이 프레임에 들어 있다). 없으면 예전처럼 걸음 두 장 + 서기. 뒷모습(↗)은 아직 걸음 두 장.

## 모델 비교 — 게임 화면에 넣어 녹화로 본 결과

`motion.py build`가 **발 쓸림**을 잰다: 디딘 발이 한 주기 동안 뒤로 쓸려 가는 거리(칸). 게임 보폭(1.9칸/주기)과 같아야
달리는 동안 디딘 발이 땅에 붙어 보인다. 제자리 걸음 영상은 이 값이 작다 → 게임에서 디딘 발이 몸과 함께 미끄러진다.

| | minimax_h3_max (서약기사 ①) | seedance_2_0_mini (각인술사 ②) | seedance_2_0_mini + 러닝머신 문구 (③) |
|---|---|---|---|
| 값 | 7.5 (5초, 480p) | 2 (4초, 480p — 실제 640px) | 2 |
| 발 쓸림(목표 1.9칸/주기) | **1.83 — 통과**(러닝머신처럼 디딘 발이 뒤로 쓸린다) | 0.67 — 제자리 걸음, 디딘 발이 65% 미끄러짐 | 0.73 + 발밑 그림자 |
| 제자리 유지(한 주기 끝 ↔ 처음 몸통 어긋남, 아틀라스 px) | 0.05 · 0.31 | 0.37 · 0.51 | — |
| 첫 프레임 = 시작 그림(차이) | 0.014 | 0.145 | 0.176 |
| 주기 · 이음 차이 | 24장(1.0초) · 0.054 | 16장(0.67초) · 0.043 | 16장 · 0.042 |
| 판정 | **달리기 · 걷기는 이 모델** | 서기(숨) · 제자리 동작에만 | 불합격 |

각인술사는 ②를 넣어 두었다 — 걸음 두 장(디딘 발이 100% 미끄러진다)보다는 낫지만 서약기사만큼 붙어 보이지는 않는다.
①로 다시 뽑으면(7.5) 고쳐진다 — 일괄 생성 때 같이.

## 남은 것 — 일괄 생성(승인 필요)

잔액 **15.25크레딧**. 1-D 나머지는 잔액의 30%를 크게 넘으므로 **사용자에게 묻고 진행한다**(아직 생성하지 않았다).
달리기 · 걷기는 발 쓸림 때문에 minimax_h3_max(7.5/개), 제자리 동작(서기 숨)은 seedance_2_0_mini(2/개)로 잡았다.
