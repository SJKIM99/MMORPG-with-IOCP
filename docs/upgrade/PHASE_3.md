## 1. 3-A 창 시스템 — 설계

| 결정 | 고른 것 | 대안 | 이유 |
|---|---|---|---|
| 창 상태 | **창 관리자(`ui/Wm`)**: 창 id(문자열)마다 위치 · 크기 · 투명도 · 잠금 · 열림 · 겹침 순서 · 열기/닫기 애니메이션. 즉시 모드는 그대로 — 그리는 함수는 매 프레임 `wm::Begin(id, …)`으로 지금 사각형을 받아 그 안에 그린다 | 창마다 객체(유지 모드) | 기존 그리기 코드 12개를 거의 그대로 둔다. 창 상태만 한곳에 모인다 |
| 겹침 순서 · 입력 가림 | 창을 **겹침 순서대로** 그린다(그리는 함수를 목록에 올려 두고 정렬). 프레임 시작에 "마우스 아래 맨 위 창"을 정하고, 그 창이 아닌 창 안의 위젯은 `Hovered/Pressed/Clicked`가 거짓 | 위젯마다 가림 검사 | 기존 위젯 호출을 바꾸지 않고 `ui` 안에서 한 번에 |
| 끌기 · 크기 | 제목줄 끌기, 가장자리 · 모서리 6px 잡기(창마다 최소/최대), 화면 가장자리 · 다른 창에 **8px 자석**, 해상도가 바뀌면 화면 안으로, 누른 창이 맨 위, 끄는 중 반투명(80%) | | 지시서 3-A |
| Esc | 겹침 순서의 **맨 위 열린 창**부터 닫는다(마지막에 누른 창) | 고정 우선순위 | |
| UI 편집 모드 | HUD 덩어리(전투 판 · 미니맵 · 퀘스트 추적 · 채팅 · 버프 · 대상 창 · 나 · 메뉴 막대)도 창 관리자에 등록 — 편집 모드에서만 테두리 · 이름표가 보이고 끌 수 있다. 배율 80~130%(덩어리마다), "기본 배치로" | HUD를 창으로 | 평소에는 HUD가 창처럼 보이면 안 된다 |
| 저장 | `config/ui_<캐릭터>.json` — 창 · HUD 덩어리 · 채팅(탭 · 필터 · 투명도 · 글자 크기 · 잠금). 작은 JSON 읽기/쓰기(의존성 없음). 기준 해상도에 대한 **비율 + 모서리 고정점**으로 저장해 해상도가 바뀌어도 같은 자리 | 픽셀 그대로 | 1280 ↔ 2560에서 오른쪽 위 미니맵이 가운데로 가지 않게 |
| 열기/닫기 | 0.14초 이징(크기 96% → 100% · 투명도), 버튼 호버 · 눌림 반응은 기존 「새김」 부품 그대로 | | DESIGN_SYSTEM 0장 |

### 1.1 3-A 구현 · 확인

**바뀐 결정**(설계 → 구현):

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 해상도가 바뀔 때 | 기준 해상도 비율 + 모서리 고정점 | **기본 자리에서 옮긴 거리**(창) · 자연 사각형의 3분할 고정점에서 옮긴 거리(HUD) + 화면 안으로 되돌림 | 창 · HUD의 기본 자리는 이미 모서리 · 가운데에 붙어 있다(미니맵 = 오른쪽 위). 거리만 저장하면 1280 ↔ 2560에서 미니맵이 오른쪽 위에 남는다(`hudres` 4해상도 겹침 0). 비율로 저장하면 창 크기가 해상도에 따라 늘지 않아 오히려 어긋났다 |
| 큰 화면 | (설계에 없음) | **UI 배율**(자동 · 100~200%) — 기본 변환 {0, 0, 배율} 위에 논리 좌표로 그린다 | 2560×1440에서 100%면 14px 글자가 모래알 같다. 편집 모드의 덩어리 배율(80~130%)과 같은 변환 틀 |
| 열기/닫기 | 크기 96% → 100% · 투명도 | 창을 **화면 크기 렌더 텍스처에 한 번 그린 뒤** 그 부분만 배율 · 투명도로 합성(열기 0.14초 · 닫기 0.12초 동안만) | 즉시 모드 그리기 코드 수십 곳에 투명도를 넘길 수 없다. 닫히는 창은 판정 없이(ui::SetInert) 한 번 더 그린다. NPC 창은 닫히면 대화 상대가 사라지므로 닫기 애니메이션 없음 |
| 버리기 확인 · 강화 연출 · 죽음 · 메뉴 · 조작 설정 | 창 | **모달 층**(wm::ModalBegin) — 떠 있으면 마우스를 혼자 갖는다 | 옮길 이유가 없고, 뒤의 창이 눌리면 안 된다 |

**구조**(`ui/Ui` · `ui/Wm` · `game/GameWindows.cpp`):
- `ui` 변환 스택: 물리 = off + 지역 × k. 판정(Hovered · Pressed · Clicked) · 가위(`BeginClip`) · 영역 등록(Block, 물리 픽셀) · 글자 래스터 크기(`Fonts().SetRenderXform`)가 변환을 따른다. rlgl은 `rlPushMatrix` 뒤 정점을 CPU에서 옮기므로 변환을 바꿔도 배치를 비울 필요가 없다 — 드로우콜이 늘지 않는다.
  텍스처 모드 전환(미니맵 캐시 · 창 애니메이션)은 `rlMatrixMode(MODELVIEW)`로 "지금 행렬"을 modelview로 되돌려 놓으므로, 그 뒤에는 `ReapplyXform`(한 번 풀고 다시 건다) — 풀 때 modelview를 단위 행렬로 다시 둔다(스택의 옛 transform이 modelview에 써지는 것을 막음).
- 입력 층: 창마다 층 번호, 프레임 시작에 "마우스 아래 맨 위 창"이 주인. 다른 층의 위젯은 판정이 거짓 — 기존 위젯 호출 수백 곳을 고치지 않고 `ui` 안에서 한 번에.
- 시험용 입력: `in::SetScriptMouse`가 `ui::SetButtonOverride`까지 — 사람과 같은 경로로 누르고 끈다(휠도 `ui::SetWheelOverride`).
- 창 12개가 `wm::Window(id, 기본 사각형)` 한 줄씩(그리는 코드는 그대로). HUD 덩어리 8개(전투 판 · 나 · 버프 · 대상 · 미니맵 · 퀘스트 추적 · 훈련 계측 + 3-C의 메뉴 막대 · 획득 알림)는 `wm::HudScope`.
- 저장: `config/ui_<캐릭터>.json` — 창(dx · dy · w · h · 잠금) · HUD(dx · dy · k) · 채팅(탭 · 필터 · 투명도 · 글자 · 시각 · 차단). 바뀐 뒤 2초에 한 번(끄는 동안은 쓰지 않는다) + 종료할 때. 의존성 없는 작은 JSON(`core/Json`), 임시 파일에 쓰고 바꿔 넣는다.

## 2. 3-B 상시 채팅창 — 설계

### 2.1 클라이언트

- 창 관리자의 창 하나(`chat`) — 늘 보인다. 기본 왼쪽 아래 420×220, 280×120 ~ 화면 60%. 잠금 · 투명도 두 값(평소 35% · 가리키거나 입력 중 85%) · 글자 3단계 · 시각 표시.
- 줄: `{채널, 보낸 이, 받는 이, 글, 시각, 아이템 고리}` — 탭마다 500줄(고리 버퍼). 채널: 일반 · 전체 · 거래 · 길드 · 귓속말 · 시스템.
- 탭: 모두 · 일반 · 길드 · 귓속말 · 거래 · 시스템 + "+"(사용자 탭 — 채널 거르기 · 우클릭 설정 · 새 줄 반짝임 켜기/끄기).
- 거슬러 보기: 휠로 올려 보는 중에는 새 줄이 와도 아래로 튀지 않고 "▼ 새 메시지 N". 새 줄은 짧게 밀려 들어온다.
- 이름 클릭 → 귓속말 · 결사 초대(Phase 5) · 차단(클라 목록). Shift+클릭한 아이템 → `[아이템 이름]` 고리(128바이트 안의 짧은 표식 `{i:아이템id:강화:희귀도}`) — 채팅에서는 툴팁.
- 입력: Enter 열기/보내기 · Esc 취소 · `/귓 이름 내용` · `/r` · `/길` · `/전`(예전 `&`도) · `/거래` · `/초대 이름` · `/일반`(자동 완성) · ↑↓ 기록 · 한글 조합 표시 · 남은 바이트(128바이트 ≈ 한글 42자).
- 머리 위 말풍선은 일반 채널만.

### 2.2 서버 · 프로토콜

| 패킷 | 방향 | 크기 | 내용 |
|---|---|---|---|
| `CS_CHAT_EX` (새) | C→S | 약 152B | `channel` · `targetName[20]` · `mess[128]` — 확장 세션만 |
| `SC_CHAT_EX` (그대로) | S→C | 168B | `channel`에 값만 끝에 추가(거래 · 길드 · 귓속말 받음 · 귓속말 보냄 · 일반(지역)) — 구조체는 한 바이트도 바꾸지 않는다 |

- 범위: **일반 = 같은 지역(Zone) 전체**(그 Zone 스레드가 자기 사용자 목록에 — 단일 작성자) · 전체 · 거래 = 서버 전체(각 10초 · 5초 재사용 대기) · 길드 = Phase 5(지금은 "결사가 없습니다") · 귓속말 = 이름 색인(없으면 시스템 메시지).
- 이름 → 세션 색인: `GameSessionManager`에 로그인 · 로그아웃 때 넣고 빼는 표(읽기 많고 쓰기 적어 `shared_mutex`).
- 도배 막기: 세션마다 토큰 버킷(5줄 / 5초) · 같은 문장 반복 제한 · 잘못된 UTF-8 거부. 어기면 시스템 메시지로 알리고 버린다.
- 접속 직후 최근 전체 대화 20줄(선택).
- 레거시 `CS_CHAT` · `SC_CHAT`(봇 경로)는 그대로 — 봇이 받는 패킷과 부하 조건이 바뀌지 않는다.

### 2.3 3-B 구현 · 확인

**패킷 · 프로토콜**(끝에만 추가 — 기존 패킷 바이트 변화 없음):

| 항목 | 내용 |
|---|---|
| `PacketType::CS_CHAT_EX` = **88** | C→S `{channel(1) · targetName[20] · mess[128]}` = **152B**(`static_assert == 152`). 확장 세션만(Route에서 `IsExtended` 검사). `PacketType`은 이제 **89개(0~88) — 127까지 38개** |
| `ChatChannel` | `Normal · World · System` 뒤에 **`Trade · Guild · WhisperIn · WhisperOut`**. 받는 쪽은 기존 `SC_CHAT_EX`(168B) 그대로 |
| `kChatHistoryBit = 0x80` | `SC_CHAT_EX.channel`의 가장 높은 비트 = 접속 직후 보내는 최근 대화(말풍선 · 알림음 없음, 조금 흐리게) |
| `SystemMessageCode` | 끝에 `ChatTooFast(채널, 기다릴 ms) · ChatRepeated · ChatBadText · ChatNoTarget · ChatNoGuild` |
| `MAX_CLIENT_PACKET_SIZE` | `ClientPacketSizeDetailV2::v12`(152B) — 서버 수신 조각 크기만 21B 늘었다 |
| DB | 바뀐 것 없음(채팅은 저장하지 않는다) |

**서버**(`Content/ChatHelper` · `GameSessionManager` · `Sector`):
- 스레드: Route가 세션의 Zone 큐로 넘기므로 모든 검사는 **보낸 사람을 소유한 Zone 스레드**에서 — 도배 상태(토큰 버킷 · 되풀이 · 채널 대기)는 `User` 안(단일 작성자).
- 일반 = **같은 지역(Zone) 전체**: 그 Zone 스레드의 섹터 표를 한 번 훑어(`Sector::ForEachUserInZone`, 50×50칸 — 빈 칸은 크기 비교뿐) 확장 세션에 `SC_CHAT_EX(Normal)`. 레거시 세션(봇 · 옛 클라)에는 예전 `CS_CHAT`과 똑같이 시야 안(섹터 3×3 · `CanSee`) `SC_CHAT` — 봇이 받는 패킷과 부하 조건이 그대로.
- 전체 · 거래 = 서버 전체 확장 세션(`SnapshotSessions` — 월드 공지와 같은 경로, 사람마다 10초 · 5초에 한 번이라 드물다). 다른 Zone의 세션에는 `PostSend`(세션별 송신 락)만.
- 귓속말 = **이름 → 세션 색인**(`GameSessionManager::RegisterName/FindByName` — 소문자 키, `shared_mutex`, 세션 표와 다른 락). 확장 세션이 게임에 들어올 때 넣고(`ChatHelper::OnEnterWorld`), 세션을 풀 때 뺀다(같은 이름으로 다시 들어온 새 세션의 자리는 건드리지 않음). 받는 사람 `WhisperIn`, 보낸 사람 `WhisperOut`(이름 = 받는 사람의 실제 이름).
- 검사 순서: UTF-8(제어 문자 · 너무 긴 표현 · 서로게이트 거부) → 토큰 버킷 **5줄/5초**(1초에 1줄씩 참) → 같은 말 **30초 안의 세 번째** → 전체 10초 · 거래 5초 → 결사(Phase 5 전엔 `ChatNoGuild`) → 귓속말 상대. 거절은 토큰을 쓰지 않는다.

## 6. 서버 부하(STRESS_TEST 전/후)

서버 변경은 3-B의 채팅 경로뿐(`CS_CHAT_EX` · 이름 색인 · 최근 대화). 같은 샌드박스(CPU 2 · Wine)에서 클라이언트 · 녹화를 모두 끈 뒤 150초씩, Phase 2와 같은 규칙(지연 100ms에서 멈춤 · 150ms에서 줄임):

| 서버 | 지연 100ms 이하 최대 봇 수 | 뒤 절반 평균 지연 |
|---|---|---|
| Phase 3 전(Phase 2 마지막 `499050c` 서버) — 1회 | 1,966 | 145.9ms |
| Phase 3 후(`e2b054a` 서버 = 마지막) — 2회 | 2,024 · 2,010 (평균 2,017, **+2.6%**) | 142.8 · 155.4ms |

- 차이는 회차 간 흔들림(Phase 2에서 잰 ±2.5%) 안이다 — 나빠지지 않았다. 봇은 레거시 `CS_CHAT`만 쓰고 확장 세션이 아니라서 **새 채팅 경로의 부하는 이 도구로 잴 수 없다**(9장의 지역 일반 채팅 비용 참고).
- 이름 색인(`_nameLock`, 세션 표 락과 따로)은 확장 세션이 게임에 들어올 때 넣고(`unique_lock`) 귓속말 때만 읽는다(`shared_lock`).
  세션을 풀 때는 봇 세션도 한 번 잠근다(해시 조회 한 번 — 봇은 이름을 넣지 않으니 대개 찾지 못하고 바로 푼다). 위 측정에 이 비용이 들어 있다.

## 9. 알려진 한계 · 실기 확인 필요

- **실기 확인 필요**: Windows 한글 IME(채팅 조합 표시 · 조합 중 Tab · Enter · ↑↓), 실제 GPU에서 창 열기/닫기 렌더 텍스처 합성 비용(샌드박스는 소프트웨어 렌더링), MSVC 빌드(새 파일 `ui/Wm` · `core/Json` · `game/Chat*` · `Content/ChatHelper`),
  STRESS_TEST 실서버 수치, 4K(창 · 글자 200%)에서 글자 래스터 캐시 크기.
- **지역 전체 일반 채팅의 비용**: 일반 한 줄 = 그 Zone의 섹터 50×50을 한 번 훑고 확장 세션 수만큼 보낸다 — 사람 수 N이면 N명이 말할 때 N²로 는다. 토큰 버킷(1초에 1줄꼴)이 상한이지만,
  한 지역에 확장 세션이 수백 명 모이면 일반을 시야 범위로 줄이는 안전장치(인원 문턱)가 필요하다. 봇(레거시)은 이 경로를 쓰지 않아 STRESS_TEST로는 잴 수 없다.
- 결사 채널 · `/초대` · 이름 메뉴 "결사 초대" · 메뉴 막대 결사/경매장 · 정산함 점은 자리만 있다(Phase 5).
- 창 배치 · 채팅 설정의 서버 저장 없음(5장 5번). 차단은 클라에서만 거른다(서버는 보낸다).
- 창 크기 조절은 채팅창만 — 다른 창은 내용 배치가 고정이라 옮기기만 된다(로스트아크도 대부분의 창은 크기 고정).
- 그림 생성 없음(Higgsfield 잔액 12.75 그대로). 메뉴 막대 아이콘은 선으로 그린 절차적 그림이다.
