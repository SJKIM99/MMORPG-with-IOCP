# 002 — 월드 배치의 Single Source of Truth는 JSON이다

**작성일** 2026-09-22
**상태** 구조 확정, 로더 미구현

## 문제

2D 시절 이 프로젝트의 맵은 사실상 코드 상수였다. 오브젝트가 몇 개 없었고
서버가 아는 좌표와 클라이언트가 그리는 좌표가 갈라질 여지가 없었다.

3D로 가면 배치 대상이 수백 개로 늘어난다. 이때 흔히 나오는 구조는
**클라이언트 씬 파일에 손으로 배치하고, 서버는 별도의 콜리전 데이터를 갖는 것**이다.
이 구조에는 특정 실패 모드가 있다.

- 클라에선 벽인데 서버 내비메시에서는 통과 → 몬스터가 벽을 뚫고 지나간다
- 클라에선 뚫려 있는데 서버에서는 막힘 → 플레이어 이동 요청이 이유 없이 거부된다

이 부류의 버그는 **특정 좌표에서만 재현되고, 배치를 수정할 때마다 되살아난다.**
QA로 전수 확인이 불가능하고, 한 번 고쳐도 다음 배치 수정에서 다시 생긴다.
원인은 개별 버그가 아니라 *진실이 두 벌 있다*는 구조 자체다.

서버 권위(§9)를 지키려면 이동 가능 여부의 판정 주체는 서버여야 한다. 그런데
플레이어가 보는 화면은 클라이언트가 그린다. 두 벌이 갈라지는 순간 서버 권위는
"서버가 맞고 화면이 틀린" 상태가 되고, 이건 사용자에게는 그냥 버그다.

## 선택

**`world/regions/*.json` 하나를 유일한 진실로 두고, 서버와 클라이언트가 같은 파일을 읽는다.**

```
world/
  manifest.json          에셋 ID → 파일 경로 / 콜리전 타입 / nav 속성 / 출처 / 라이선스
  regions/
    town.json            배치 엔트리 (Single Source of Truth)
    field_01.json
    dungeon_01.json
  build/
    town.obj             콜리전 메시 병합 결과 (Recast 입력)
    town.navmesh         Detour 바이너리 (서버 로드)
```

배치 엔트리:

```json
{
  "asset": "prop_tree_pine_01",
  "pos": [128.0, 0.0, -64.5],
  "yaw": 1.5708,
  "scale": 1.0,
  "collision": "static_walkable | static_blocker | none",
  "nav": "include | exclude | area:water"
}
```

두 갈래로 갈라지지만 **입력이 같다.**

```
                    ┌─→ tools/build_collision.py → build/*.obj
regions/*.json ─────┤        → tools/build_navmesh → build/*.navmesh → 서버 dtNavMesh
                    │
                    └─→ Godot 임포터 스크립트 → 씬 노드 생성 (렌더 + 클라 콜리전)
```

따라오는 규칙:

- **Godot 씬 파일에 손으로 오브젝트를 배치하지 않는다.** 씬은 산출물이지 입력이 아니다.
- 배치 생성은 `tools/gen_layout.py`에 프로시저럴로 작성하고 **seed를 고정**한다. 같은 seed는 같은 월드를 낳는다.
- 스폰 포인트와 순찰 웨이포인트도 같은 JSON에 넣는다. 코드에 하드코딩하지 않는다(§8).
- 에셋의 배율·콜리전 타입은 `manifest.json` **한 곳에만** 적는다. 배치 엔트리는 이를 참조한다.

## 대안

**(a) Godot 씬(`.tscn`)을 진실로 두고 서버가 파싱한다**
씬 포맷이 Godot 버전에 종속된다. 엔진을 올릴 때마다 서버 파서가 깨진다.
무엇보다 **서버가 클라이언트 엔진의 파일 포맷을 아는 역방향 의존**이 생긴다.
클라이언트를 교체하면 서버를 고쳐야 한다. 버렸다.

**(b) 서버 전용 콜리전 데이터를 따로 관리한다**
정확히 위 "문제"에 적은 실패 모드 그 자체다. 두 벌을 사람이 동기화해야 한다.

**(c) 런타임에 클라이언트가 배치 정보를 서버에 보고한다**
서버 권위 위반(§9). 클라이언트가 보내는 것은 입력뿐이다. 논외.

**(d) 손 배치 + 자동 export 스크립트**
(b)보다는 낫지만 **export를 잊으면 갈라진다.** 사람이 기억해야 하는 절차는
바쁠 때 반드시 빠진다. "잊어도 갈라지지 않는 구조"가 목적이므로 반쪽이다.

## 결과

**구조로 보장되는 것** — 콜리전 불일치가 *발생할 자리 자체가 없다.*
같은 파일에서 나온 두 산출물이므로, 갈라지려면 빌드 파이프라인에 버그가 있어야 한다.
"동기화를 잊었다"로는 갈라질 수 없다.

**실제로 이득이 드러난 사례 (2026-09-22, 에셋 정리 중)**
KayKit Medieval Builder Pack의 `house` 모델을 실측하니 1.69 × 0.91 × 1.66 m 였다.
같은 팩의 캐릭터가 2.17 m 이므로 집이 캐릭터보다 낮다. 이 팩은 격자 전략맵용
미니어처라서 마을로 쓰려면 확대가 필요하고, `manifest.json`에 `scale: 6.0`으로 적었다.

손 배치 구조였다면 **Godot에서 ×6으로 놓고 서버 콜리전 OBJ는 ×1로 뽑히는** 사고가
날 자리였다. 배율이 manifest 한 곳에 있으므로 서버 콜리전 생성과 클라 렌더가
같은 값을 읽는다. 배율을 조정할 때도 고칠 곳이 하나다.

**현재 구축된 것**
- `world/manifest.json` — 에셋 51개 등록 (전체 300여 개 중 Week 1~2 범위)
- `tools/verify_assets.ps1` — 51/51 에셋 + `.gltf`가 외부 참조하는 `.bin`/`.png` 101/101 존재 확인, exit 0
- 벤더 에셋 255MB는 `.gitignore` 대상. 출처·라이선스는 manifest에, 받는 절차는 README에 기록

## 남은 한계

- **로더가 아직 없다.** 서버 측 `regions/*.json` 파서와 Godot 임포터 스크립트를
  둘 다 작성하지 않았다. 지금은 스키마와 파이프라인 형태만 확정한 상태다.
  "구조로 보장된다"는 주장은 로더 2개가 붙어야 실증된다.

- **일치를 검증하는 도구가 없다.** 현재 보장은 "같은 입력을 읽으니 같을 것"이라는
  구조적 보장이고, 빌드 파이프라인 자체에 버그가 있으면 여전히 갈라진다.
  최소한의 확인으로 Week 2에 **서버 내비메시를 클라이언트에 디버그 렌더**해
  눈으로 대조한다(§7 — 클라는 내비메시를 경로 디버그 시각화에만 쓴다).
  자동 대조 도구는 스코프 밖으로 둔다.

- **배율 9건이 미검증이다.** `manifest.json`의 `bld_*` 엔트리는 전부
  `"scale_verified": false`다. 실측값에서 역산한 제안값일 뿐 Godot에서 렌더해
  확인하지 않았다. Week 4 아트 단계에서 확정한다.

- **기동 시 파싱 비용을 측정하지 않았다.** 현재 월드 규모(마을 256², 필드 512²,
  인던 128² — §4)에서는 문제될 양이 아니라고 보지만 측정한 적은 없다.
  타일 스트리밍으로 확장하면 타일 단위 lazy load가 필요해진다.
  스트리밍 인터페이스만 만들고 타일 수는 적게 유지한다는 §4 방침과 연결된다.
