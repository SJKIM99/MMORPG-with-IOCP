# 리니지풍 컨텐츠 확장 (서버) — `newclient` 브랜치

`dev` 브랜치의 IOCP 서버 위에 리니지 스타일 컨텐츠 네 묶음과, 새 2D 클라이언트(`Client2D/`)용
확장 프로토콜을 올렸습니다. 클라이언트 빌드/조작은 [`Client2D/README.md`](../Client2D/README.md)를 보세요.

## 지킨 원칙

1. **기존 패킷은 한 바이트도 바꾸지 않는다.** `PacketType`·`SystemMessageCode` 등 모든 열거형은 **끝에만** 추가했습니다.
2. **확장 세션 분리.** 새 클라이언트는 `USER_LOGIN_EX_REQ`로 접속하고, 확장 패킷은 그 세션에만 보냅니다.
   `STRESS_TEST` 봇·기존 클라이언트는 `USER_LOGIN_REQ`를 쓰므로 받는 패킷 구성과 부활 규칙(같은 Zone 무작위 위치)이 예전과 같습니다
   → 부하 테스트 조건이 보존됩니다.
3. **서버는 사실만, 연출은 클라이언트.** `EFFECT_NFY`는 “어디서 누가 무엇을”만 알리고 파티클/사운드/흔들림은 클라이언트가 정합니다.
4. **데이터는 공유 헤더 하나.** `Data/WorldData.h`(지역·마을·NPC·상점·충돌), `Data/MonsterTable.h`, `Data/LevelTable.h`(레벨·전투·강화·성향 규칙),
   `Item/ItemTableData.h`를 서버와 클라이언트가 같이 include합니다. 레이아웃·스폰 좌표가 어긋나면 `static_assert`로 **빌드가 실패**합니다.
5. **멱등성.** 상점/텔레포트 요청은 `seq`를 실어 보내고, 서버가 플레이어별 마지막 번호를 기억해 재전송을 무시합니다.

## 1. 몬스터 종족 · 지역 난이도 · 보스

- 서버 Zone(500×500칸, 4×4)을 그대로 **16개 지역**으로 삼았습니다. 지역마다 바이옴·난이도(★1~5)·스폰 가중치·텔레포트 도착점/요금이 있습니다.

  | | | | |
  |---|---|---|---|
  | 0 서리 설원 ★3 | 1 고요한 숲 ★2 | 2 용의 협곡 ★4 | 3 화염 둥지 ★5 |
  | 4 요정의 숲 ★2 | **5 여명의 평원 ★1 (마을)** | 6 황혼의 폐허 ★3 | 7 오크 요새 ★3 |
  | 8 안개 늪지 ★3 | 9 푸른 초원 ★1 | 10 모래바람 사막 ★2 | 11 붉은 황무지 ★4 |
  | 12 망자의 묘지 ★4 | 13 파도 해안 ★2 | 14 개미굴 ★3 | 15 심연의 문 ★5 |

- **일반 몬스터 28종**(젤리·고블린·늑대·오크 전사·해골·골렘·드레이크·악마 전사 …), 선공/비선공, 레벨·HP·공격력·경험치·아데나 범위를 표로 관리.
- **필드 보스 6종**: 서리 거인, 오크 대족장, 데스나이트, 여왕 개미, 화염 드레이크, 바포메트. 고정 위치에 5분 주기로 재등장하고,
  주기적으로 **내려찍기**(`BossSlamCast` 경고 → 잠시 뒤 `BossSlamImpact` 범위 피해)를 씁니다. 출현/처치는 `WORLD_NOTICE_INF`로 전 서버 공지.
- 레벨 50까지 경험치 표, 레벨별 최대 HP·기본 공격력·자연 회복량(마을 2배). 데미지 ±15% 편차, 치명타 8%(×1.6).

## 2. 아데나 · 상점 · 강화

- **아데나**는 인벤토리 슬롯이 아니라 플레이어 지갑 값입니다(`Players.adena`). 몬스터가 떨어뜨리고, 줍기/구매/판매/텔레포트 때 `ADENA_INF`로 갱신.
- **상점**: 잡화상(물약 3종·귀환/순간이동 주문서·초록 물약·강화 주문서), 대장장이(나무 검·철검·오리하루콘 단검). 매입은 두 상인 모두.
  NPC 근처(체비셰프 3칸)인지 서버가 검증합니다.
- **텔레포터**: 지역별 요금(100~3,000 아데나)으로 각 지역 도착점으로 이동.
- **무기 강화**: +6까지 100%, 이후 40→30→22→15→10→8→7→6→5%. 실패하면 무기가 **증발**합니다. 축복받은 주문서는 안전 구간에서 +1~3.
  +6까지 공격력 +1씩, 그 위로 +2씩. **+9 이상 성공은 월드 공지.** 판정·소모·DB 저장은 한 트랜잭션입니다.
- 초보자 지원: 새 캐릭터에게 나무 검(장착)·빨간 물약 20·귀환 3·순간이동 2·초록 물약 2·강화 주문서 1·1,000 아데나.

## 3. 마을 · 귀환 · 사망 패널티

- **여명의 마을**(지역 5 중앙 44×44칸): 성벽·성문·건물·분수·NPC 5명. 마을 전체가 **안전지대**(PvP 불가, 몬스터 진입/피해 불가, 회복 2배).
- **마을 귀환 주문서**: 마을 부활 지점으로. **순간이동 주문서**: 현재 지역 안 무작위 칸(마을·막힌 칸 제외).
- **초록 물약**: 5분 가속(이동 쿨타임 500 → 330ms).
- **사망**: 몬스터에게 죽으면 현재 레벨 필요 경험치의 5% 손실(레벨 다운 없음, PvP 사망은 손실 없음). 확장 세션은 “마을에서 다시 시작”(`USER_RESTART_REQ`)
  또는 30초 뒤 자동으로 마을에서 부활합니다.

## 4. PK · 성향치

- 몬스터를 잡으면 성향치가 오릅니다(몬스터 레벨/2, 최소 1). **500 이상 = 라우풀(파란 이름).**
- 다른 플레이어를 먼저 때리면 **60초 보라색 이름**(정당방위 대상). 보라색·카오틱 상대를 죽이는 것은 벌칙이 없습니다.
- PvP 피해는 평타의 70%(한두 대에 끝나지 않도록).
- 무고한 플레이어를 죽이면 **성향치 −1000, PK 횟수 +1 → 카오틱(빨간 이름)**, 전 서버 공지.
- **카오틱이 죽으면 40% 확률로 소지 아이템 하나를 떨어뜨립니다**(강화 수치 유지).
- 안전지대 안에서는 공격 자체가 거부됩니다(`SafeZoneNoCombat`).

## 확장 프로토콜

| 방향 | 패킷 | 내용 |
|---|---|---|
| C→S | `USER_LOGIN_EX_REQ` | 확장 로그인(버전 포함) |
| C→S | `USER_RESTART_REQ` | 사망 시 마을에서 다시 시작 |
| C→S | `USER_TARGET_ATTACK_REQ` | 대상 지정 근접 공격(몬스터/플레이어 공통, PK 포함) |
| C→S | `ITEM_ENCHANT_REQ` | 강화 주문서 사용(주문서 슬롯, 무기 슬롯) |
| C→S | `SHOP_BUY_REQ` / `SHOP_SELL_REQ` / `NPC_TELEPORT_REQ` | 상점·텔레포트(`seq`로 멱등) |
| S→C | `USER_INFO_EX_INF` | 내 레벨·경험치·다음 레벨 경험치·아데나·성향치·PK·공격력·상태 플래그 |
| S→C | `SUBJECT_INFO_EX_NFY` | 주변 플레이어의 레벨·성향치·보라/가속/안전지대·무기 강화 수치 |
| S→C | `ITEM_LIST_EX_ACK` / `ITEM_SLOT_EX_INF` | 강화 수치를 포함한 인벤토리 스냅샷 / 슬롯 하나 갱신(모든 슬롯 변경 경로에서) |
| S→C | `ADENA_INF` | 아데나 변경(사유 포함) |
| S→C | `ENCHANT_RESULT_ACK` / `SHOP_RESULT_ACK` | 강화 결과 / 구매·판매·텔레포트 결과 |
| S→C | `SUBJECT_DAMAGE_NFY` | 누가 누구에게 얼마를(치명타·스킬·사망 플래그) |
| S→C | `EFFECT_NFY` | 이펙트 트리거(십자베기·레벨업·물약·순간이동·강화·보스 내려찍기·PK·부활·보스 출현) |
| S→C | `WORLD_NOTICE_INF` | 전 서버 공지(보스 출현/처치, 고강화 성공, PK) |
| S→C | `SC_CHAT_EX` | 채널 채팅(일반/전체/시스템, 보낸 사람 이름 포함) |

확장 패킷도 `STRESS_TEST`의 수신 버퍼(255바이트)를 넘지 않도록 `static_assert`로 크기를 묶었습니다.

`Database/setup.sql`을 다시 실행하면 됩니다(`IF NOT EXISTS` — 기존 데이터 보존).

- 프로시저: `ExtractPlayerInfo`·`GetInventory` 반환 컬럼 추가, `SaveInventorySlot`·`SaveTwoInventorySlots`에 강화 수치 파라미터(기본값 0, **끝에 추가**),

  아데나/성향치는 인벤토리와 같은 playerId 샤드로 저장되어 순서가 보장됩니다.
