# Dark Fantasy Storybook MMORPG — 고도화 설계 (V2)

> 목표: "기능이 많은 게임"이 아니라 **10~20분 플레이 후 한 번 더 하고 싶은 게임**.
> 우선순위: Game Feel > 재미 > 조작감 > 전투 피드백 > 성장 재미 > 콘텐츠 양.
> 원칙: 서버가 권위(이동 검증·판정·피해·아이템·퀘스트·길드), 클라이언트는 입력·표현·예측.
> 레거시 패킷/STRESS_TEST 봇 동작은 바꾸지 않는다(새 타입은 끝에만 추가).

## 1. 현재 구조 분석 (newclient 브랜치 기준)

### 클라이언트 (Client2D, C++20 + raylib, 약 12.4k줄)
| 영역 | 현재 | 문제(재미 관점) |
|---|---|---|
| 구조 | `Game` 한 클래스가 입력·예측·패킷·그리기·UI를 모두 가짐(Game/GameNet/GameDraw/GameUi 4개 파일) | 새 시스템(직업·스킬·퀘스트·길드)을 얹을 자리가 없음 → 하위 시스템으로 분리 필요 |
| 렌더링 | 깊이 버퍼 기반 2D 배치(`gfx`), GLSL 지형, 절차적 벡터 캐릭터/몬스터/소품, 조명 RT, 가려짐 실루엣 | 캐릭터가 모두 같은 체형 — 직업/장비 차이가 보이지 않음 |
| 입력·이동 | 타일 한 칸씩, **응답 1개 대기 후 다음 이동**(0.54s 간격), 대각선도 같은 시간, 가감속 없음 | 딱딱함의 핵심 원인. 지연이 크면 이동 자체가 느려짐, 방향 전환이 각짐, 걷기 애니메이션이 시간 기준이라 발이 미끄러짐 |
| 전투 | 기본 공격(0.62s) + 십자베기 1개, 히트스톱·번쩍임·숫자·흔들림 있음 | 스킬이 1개, 직업 없음, 몬스터가 전부 같은 근접 패턴(예고 없음) → 피하는 재미·연계 재미 없음 |
| 아이템 | 18종, 무기만 장착, 등급 5단계(무기에만 의미), 강화 | 방어구/장신구/옵션/세트 없음 → "오 이거 좋은데?"가 없음 |
| 스탯 | 레벨 기반 HP/공격력만 | 성장 선택이 없음 |
| UI | 소지품·상점·강화·텔레포트(현 옛길 이동)·지도·도움말 | 장비창/캐릭터창/퀘스트/길드 없음 |
| 카메라 | 추적 + 진행 방향 리드 + trauma 흔들림 + 줌 펀치 | 양호. 지역/스킬 연출만 보강 |
| 네트워크 | 논블로킹 TCP, 프레이밍, 확장 로그인 | 이동 예측 1개 제한, 재접속 없음 |

### 서버 (GameServer, IOCP, 약 11.8k줄)
- Zone(500×500) 단위 액터 스레드, 패킷은 `ZoneManager::EnqueueBySession`으로 해당 Zone 스레드에서 `Route::Dispatch`.
- 이동: 8방향 `USER_MOVE_REQ`, **`now > last + 500ms` 엄격 판정**(지터로 두 패킷이 붙어 오면 두 번째는 조용히 버려짐 → 고무줄 현상), 대각선 1칸 = 직선과 같은 비용.
- 시야: `VIEW_RANGE = 5`(11×11칸) 상수 — 원거리 직업/탐험 재미에 너무 좁다.
- 전투: 근접 1칸, 스킬 1개, 몬스터 AI는 추적 + 근접 공격(보스만 장판 예고).
- 패킷 타입은 `char` 1바이트로 읽음(`packet[2]`) → 128개를 넘으면 부호 문제 → `uint8_t`로 읽도록 수정 필요.

## 2. 목표 구조

### 2.1 이동·조작감 (P2)
- **서버**: 토큰 버킷식 이동 검증. `start = max(clock, now - 200ms)`, `start <= now + 150ms`면 허용, `clock = start + cost`.
  비용 = 기본 걸음(직선 280ms, 대각선 ×√2) ÷ 이동속도 배율(스탯·가속). 지터로 몰려 온 패킷도 정상 속도면 통과.
- **`USER_MOVE_EX_REQ(dir, seq)` → `USER_MOVE_EX_ACK(seq, x, y, ok)`**: 확장 세션은 순번으로 예측을 맞춘다(거절도 즉시 응답).
- **클라이언트**: 예측 이동 최대 3개까지 앞서 보냄(지연이 커도 멈추지 않음), ACK 순번으로 보정.
  - 8방향 WASD(화면 기준), 막히면 진행 방향에 가장 가까운 열린 방향으로 **미끄러짐**.
  - 입력 우선순위: WASD > 마우스 누르고 있기 > 클릭 경로. WASD를 누르면 경로/자동 공격 목표를 즉시 취소.
  - 표시 위치 = 논리 위치를 임계 감쇠 스프링으로 따라감 → 출발 가속·정지 감속·모서리 둥글게.
  - 걷기 위상은 **이동 거리 기준**(발 미끄러짐 제거), idle↔walk↔run은 속도로 블렌드.
  - 다른 개체는 걸음 간격을 추정해 보간(버퍼링), 옛길 이동/존 이동은 스냅.
- **시야**: `GViewRange` 런타임 값(기본 9, `--view-range 5`로 부하 테스트 조건 재현). 클라 안개도 서버 값을 따른다.

### 2.2 전투 (P3)
- 흐름: 입력 → 준비(windup) → 모션 → 판정(서버) → 히트스톱 → 임팩트/숫자/피격 반응/파티클/사운드.
- 서버 권위 **넉백**(강공격/스킬에 1~2칸, 막히면 벽 충돌 추가 피해·짧은 경직), 상태이상(기절·빙결·둔화·화상·중독).
- **몬스터 공격 패턴**: 근접 / 돌진(예고선) / 원거리 투사체 / 범위 장판 / 도약. 모든 강공격은 예고(windup) 후 판정 → **피할 수 있다**.
- 클라: 콤보 카운터(연속 적중), 연계 표시, 효과 과잉 방지(동시 파티클/흔들림 상한).

### 2.3 직업·스킬 (P4~5) — `Data/SkillTable.h` 서버/클라 공용
| 직업 | 역할 | 핵심 연계 |
|---|---|---|
| 서약기사 | 근접·수호·반격 | 방패 강타(기절) → 검격/회전 베기(기절 대상 추가 피해) → 단죄(기절·빈사 대상 폭딜) · 철벽 태세 중 피격 시 반격 |
| 각인술사 | 원거리·제어·폭딜 | 서리 각인(빙결) → 화염 고리(빙결 대상 **증발 폭발**) · 낙성(빙결 대상 **산산조각**) → 벼락 사슬(표식/화상/빙결 대상 전도) · 옛길 도약 |
| 밤사냥꾼 | 근접 딜·기동 | 그늘 걸음(대상 뒤로) → 후방 습격(뒤에서 치명) → 독 칼날(중독 중첩) → 그믐 베기(중독 소모 폭딜) · 잔상 회피 |

직업 · 기술 이름은 [WORLD.md](WORLD.md)의 규칙을 따른다(서약 기사단 · 올란의 새김 글자 · 변경의 밤).

- 서버: 시전 검증(직업·레벨·쿨다운·MP·사거리), 판정 모양(단일·원·선·부채꼴·십자), 상태이상, 연계 판정.
- 연계 성공 시 `DAMAGE_COMBO` 플래그 + 연계 id → 클라가 추가 이펙트·사운드·짧은 히트스톱·"연계!" 표시.
- 클라(구현됨): 기본 공격 Space + 기술 1~5, 쿨다운 스윕·쿨다운 끝 반짝임, 선입력, 사거리 밖이면 다가가서 시전,
  기술 칸에 마우스를 올리면 사거리/범위 미리보기. **전투는 키보드로만** — 대상은 Tab/자동(바라보는 쪽 우선),
  지점 기술은 대상 발밑, 방향 기술(돌진·회피·도약)은 누르고 있는 WASD 방향(없으면 대상/바라보는 쪽).
- 구현 파일: 서버 `Combat/SkillHelper`·`Combat/CombatHelper`·`Combat/StatusSet.h`, 공용 `Data/CombatData.h`,
  클라 `game/GameCombat.cpp`(시전·적중 표시·지연·연계), `fx/SkillFx.cpp`(기술별 연출), `render/Actors.cpp`(직업별 몸·기술 자세).

### 2.4 스탯·아이템 (P6) — 구현됨
- 기본 능력치 STR/DEX/INT/VIT/WIS/LUK(직업별 성장 + 레벨당 자유 1포인트) → 전투 능력치(HP/MP/공격/마공/방어/마방/공속/이속/치명/치피/명중/회피/관통/쿨감/저항).
  확장 세션의 이동속도는 이 값(DEX · 장비 "이동 속도")을 쓰고, 클라는 `USER_STATS_INF.stats.moveSpeed`로 같은 값을 예측한다.
- **장비 부위 8개**: 무기 · 투구 · 갑옷 · 장갑 · 신발 · 망토 · 목걸이 · 반지(`EquipSlot`). 부위마다 하나씩 장착(`Inventory::TryEquip`은 같은 부위만 벗긴다).
  확장 세션은 직업 전용 무기(`classMask`)·착용 레벨(`reqLevel`)을 검사한다. 레거시 세션은 예전처럼 무기만 다룬다.
- **아이템 표**: 1~20(예전) + 21~58(직업 무기 8 · 방어구/장신구 18 · 세트 12). 예전 등급(`grade`)은 "적어도 이 희귀도"라는 바닥.
- **희귀도 6단계**(일반·고급·희귀·영웅·전설·신화) — 인스턴스 값 64비트(`Data/ItemRules.h ItemInstance`):
  희귀도 · 옵션 4줄(종류 5비트 + 값 8비트) · 특수 효과 4비트 · 신화 강화 1비트. DB `Inventory.extra BIGINT`, 패킷 `ITEM_DETAIL_INF`.
  - 옵션 수: 0/1/2/3/3/4, 전설 이상은 특수 효과(천둥의 일격 · 피의 갈증 · 서리 손길 · 처형자 · 메아리 · 수호의 맹세 · 잔불 · 맹독), 신화는 강화판.
  - 옵션은 부위별 후보에서 겹치지 않게, 단계(tier)·희귀도로 정해진 범위 안에서만 굴린다. 줍는 사람 직업의 주 능력치가 3배 잘 붙는다.
  - 전설 이상 무기·목걸이는 절반 확률로 "기술 강화"(그 직업 기술 하나 피해 +25~50%).
  - 바닥보다 높게 나오면 기본 성능 단계마다 +8%, 상점 매입가 ×1.3~×7.
- **세트 3종**(서약의 갑주 · 이레린의 노래 · 은늑대): 2부위 · 4부위 효과(옵션과 같은 형식) + 4부위 특수 효과.
- **보상 루프(제한된 무작위)**: 몬스터 단계별 "바닥 위 +0~+4" 가중치(보스는 따로), 신화는 한 번 더 관문(8% · 보스 15%),
  천장: 장비 10개 동안 희귀 이상이 없으면 다음은 희귀 이상, 40개 동안 영웅 이상이 없으면 영웅 이상(`User::m_pity*`, 진행 데이터 v2에 저장).
  확장 세션이 잡은 몬스터는 예전 표 굴림 + 단계별 방어구·장신구·직업 무기 추가 굴림(8~12%, 보스 3개), 예전 표의 검은 각인술사/밤사냥꾼에게 60% 확률로 직업 무기로.
  "희귀품 발견"·"그로시 획득" 옵션이 굴림에 들어간다. 레거시 세션(봇)이 잡은 몬스터는 예전 표 그대로.
- **능력치 계산은 서버·클라 같은 함수**: `ItemRules::Accumulate` + `StatRule::Compute` — 툴팁의 ▲/▼ 비교 숫자 = 입었을 때 서버가 보내는 숫자.
- **클라 UI**: 소지품(장비창 8칸 + 캐릭터 미리보기 + 가방 30칸), 희귀도 테두리·바탕 빛, ▲ 갈아입을 만한 장비, 새 장비 반짝임,
  검색(이름·희귀도·부위·옵션·세트), 정리(`ITEM_SORT_REQ` — 서버가 두 칸 교환의 연속으로 수행해 도중에 죽어도 복제/유실 없음),
  툴팁(기본 성능 · 옵션 · 특수 효과 · 세트 진행 · 착용 조건 · 능력치 변화) + 같은 부위 착용 장비 비교 툴팁, 끌어서 입기/벗기, 희귀 장비 버리기 확인.
- **루팅 연출**: 바닥 장비 희귀도(`SUBJECT_INFO_EX_NFY.weaponGrade`) → 희귀도별 바닥 빛·도는 고리·빛기둥(희귀부터, 전설·신화는 높고 반짝임), 이름 표시,
  떨어지는 순간 희귀도별 소리, 획득 시 영웅 이상 알림 · 전설/신화 배너 · 빛기둥 · 화면 흔들림, 신화는 월드 공지(`WorldNoticeCode::RareLoot`).
  획득 판정은 슬롯 알림 묶음이 가라앉은 뒤 "처음에 없던 (종류, 인스턴스 값)"만 — 교환·정리를 획득으로 착각하지 않는다.
- **외형**: `PLAYER_LOOK_NFY`(주변 확장 세션) — 투구 모양(두건 · 철 투구 · 기사단 투구 · 서약의 투구 · 이레린 두건), 갑옷 색/가슴판, 망토, 장갑·신발 색,
  영웅 이상 무기 희귀도 빛(신화는 반짝임), 방어구 희귀도 발밑 빛. 캐릭터 창에 장비 효과(특수 효과 · 기술 강화 · 획득 보너스 · 세트).
- 구현 파일: 공용 `Data/ItemRules.h`, `Item/ItemTableData.h` · `ItemTableRow.h`; 서버 `Item/Inventory`(부위 장착 · 합산 · 정리 · 판매가),
  `User/UserHelper`(드롭 굴림 · 상세/외형 패킷), `Combat/SkillHelper`·`CombatHelper`(기술 강화 · 특수 효과), DB `Database/setup.sql`(extra 컬럼 · 프로시저);
  클라 `game/GameItems.cpp`, `render/Icons.cpp`(방어구·장신구 아이콘), `render/Actors.cpp`(장비 외형).

### 2.5 퀘스트·시나리오 (P7) — 「멈춘 심장」
제1장 늦어지는 새벽(데니차) → 제2장 속삭이는 숲(올벤 숲) → 제3장 세 번의 종소리(캄파나 폐허) → 제4장 깨어진 서약(서약의 언덕) → 제5장 심장의 불씨(칼둔 균열, 그라목).
줄거리 · 이름은 [WORLD.md](WORLD.md). 장이 바뀔 때마다 장 그림 띠가 지나가는 장 제목 카드, 끝나면 엔딩(하르벤이 다시 뛴다).

### 2.5.1 살아 있는 마을 (구현됨)
- 서버 권위 NPC 배회: `Npc/NpcHelper`가 마을 Zone 스레드의 타이머(`EV_NPC_TICK`, 0.25초)로 NPC 20명을 움직인다.
  집 주변 반경 안에서 너비 우선 경로, 걸음 시간(NPC별), 대화 중 멈춤, 가까운 사람에게 인사, 혼잣말(`Data/NpcTalk.h`).
  NPC는 Sector 오브젝트가 아니라 레거시 세션/봇에는 아무것도 가지 않는다. 마을에 새로 들어온 확장 세션에는 `NPC_LIST_NFY`.
- 상호작용: `NPC_TALK_REQ`(서버가 NPC의 **지금 위치**로 거리 확인) · `NPC_SERVICE_REQ`(사제 치유 기도, 여관 수프 30 그로시).
  상점/옛길 이동의 거리 판정도 NPC의 지금 위치를 쓴다(`NpcHelper::IsNear`).
- 클라: 받은 칸 사이를 걸음 시간 동안 보간해 걷게 그림, 말풍선, [F] 표시, 동물 쓰다듬기(하트), 음유시인의 음표·류트 소리, 웅얼거리는 목소리.
